# Defragmenter 1.8.0-246

Rebuilds Test Media around its disk workflow and corrects a real NTFS analysis bottleneck and missing progress reporting.

- Keeps disk selection, Build → Qualify → Verify and operation progress visible. Layouts, Details and Live log share the results workspace; only result content scrolls.
- Makes all 21 filesystem tiles interactive, with a selected result inspector, full diagnostic details and clipboard copying. Logs retain the final worker output and can be viewed or copied during an operation.
- Preserves the approved graphical colours and Common-owned MB Corpo A/S typography. Compact sizing replaces the large repeated summary cards.
- Replaces NTFS catalogue-wide searches per stream with one sorted logical-stream index. Owner, attribute type and case-sensitive stream name still determine split-stream qualification; catalogue order, placement and safety policy are preserved.
- Streams analysis phases through both local and administrator execution. NTFS MFT scans report record counts; availability checks report their phase, and the UI shows elapsed time and unknown gauges until a final validated map arrives. Stop drains both streams before completing.
- Adds the group, bitmap block and expected/actual checksum to an EXT bitmap rejection. This improves diagnosis without treating the supplied error as proof of physical disk corruption or bypassing validation.

Validation includes a warnings-as-errors native build, real GTK rendering with verified bundled MB fonts, filesystem-tile inspection and fixed-control tests, a 100,000-stream NTFS regression, local/administrator progress transport and cancellation tests, and ASan/UBSan. A native NTFS fixture scan produced valid allocation JSON and progress events without changing its source bytes. The indexing regression took 0.014 CPU seconds in the release build; this is not a timing claim for the user's complete physical-volume scan. Full hosted quality and sanitizer gates are required for publication.
