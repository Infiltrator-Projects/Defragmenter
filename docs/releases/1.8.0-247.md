# Defragmenter 1.8.0-247

- Remove the remaining repeated free-run search from NTFS planning while preserving canonical first-fit placement and Growth reserves. A 100,000-stream fragmented-free-space regression checks exact placements.
- Scan the NTFS MFT once for analysis and both availability decisions. Plan each mode against a private copy of the original allocation bitmap; dirty, malformed, hibernated and unsupported layouts remain rejected.
- Refresh checksum-verified EXT descriptors and retry rejected read-only bitmap pairs. A failed read or checksum never creates a valid cache entry. Writable readers retain their locked descriptor snapshot and mounted writes remain refused.
- Keep native analysis progress out of error text, describe a mounted EXT view accurately, and require reopening a desktop whose executable was replaced during an update.
- Stop the whole local read-only analysis process group so child processes cannot leave the UI waiting on open output pipes. The cooperative mapper cancellation and bounded force-stop fallback remain in place.

The approved colours, MB fonts and Test Media layout from 1.8.0-246 are retained. The user's physical EXT volume has not been reproduced here; persistent checksum failure still prevents an unverifiable map or write.
