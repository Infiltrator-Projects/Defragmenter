# Defragmenter 1.8.0-261

This release is the result of a repository-wide forensic engineering review against the canonical Infiltrator Engineering Philosophy and Defragmenter's maintained architecture, design, decision, validation, safety and release contracts.

## Significant changes

- Removed CMake's unused `project(... VERSION 1.8.0)` declaration so `defragger/VERSION` remains the single source-version authority.
- Added `defragger/ci/preflight.sh` to the audited release-governance boundary. Runner/toolchain prerequisites can no longer change after the governance baseline without making publication fail closed.
- Strengthened the release-contract regression to prove that workflows, preflight, publication logic and the release-gate test are all included in the governance audit.
- Kept the release path single-build: qualification creates and verifies the final Debian and local `.run` artefacts once; publication downloads those exact SHA-bound artefacts and never rebuilds them.
- Corrected maintained documentation that still described release-time rebuilding, obsolete Classic HFS limits and obsolete APFS checkpoint-history rejection.
- Reworded release identity documentation to match the mechanism actually enforced: exact commit, tag target, release target, expected asset set and SHA-256 digests are treated as a write-once project contract without claiming GitHub's separate platform immutable-release flag is enabled.
- Removed the completed native-GUI migration note and stale version-specific performance note. Current ownership, performance and presentation requirements remain in the canonical documentation, code and tests.
- Re-advanced the exact audited production and release-governance baselines after the forensic changes.

## Deliberately unchanged

- The large per-filesystem native engines were not split simply because of file size. Their format-specific cohesion is intentional; arbitrary decomposition would move complexity without reducing it.
- The remaining Python GUI/service material remains source/test-only and is not installed. It still provides regression-oracle value for behavioural parity; removal should occur only after equivalent native tests demonstrably cover those contracts.
- The exact Infiltratr Common 1.19.38 pin remains unchanged because the reviewed local uses match its generic contracts and product-specific filesystem semantics remain locally owned.

No filesystem writer safety boundary is weakened by this release.
