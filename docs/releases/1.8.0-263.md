# Defragmenter 1.8.0-263

## Forensic result

This release follows a fresh repository-wide forensic pass against the canonical Infiltrator Engineering Philosophy and the maintained architecture, design, decision, validation, safety and release contracts.

## Correctness and safety

- Correct the filesystem-neutral Linux block-topology walker. Partition sysfs nodes own `holders/` but do not own the whole-disk/stacked-device `slaves/` relation directory; treating both as mandatory caused valid partitions to abort analysis with `validate block-device topology: No such file or directory`.
- Make partition-parent discovery fail closed once sysfs has identified a partition. A containing-disk device-number read can no longer be silently ignored, because doing so could hide an overlapping whole-disk mount or swap relation.
- Add a black-box host-partition regression through `ld_device_number_is_mounted()`. The test validates the production Linux/sysfs boundary without duplicating the topology algorithm and skips only on a runner that exposes no partition nodes.

## Complexity and ownership reduction

- Remove the temporary five-runner Windows smoke/hold workflow. It was infrastructure experimentation, not Defragmenter qualification, and had no place in the maintained product repository.
- Keep the release invariant's exact workflow inventory, but update its expected set to the deliberately minimal maintained surface: qualification plus publication. This preserves the protection against stray CI files instead of weakening the test after removing the obsolete workflow.
- Remove the local `.run` builder's duplicate hard-coded Common SHA/version policy. The superproject gitlink now supplies the exact dependency identity; the builder archives that exact commit, while CMake remains the executable authority for the supported Common API/version contract.
- Correct current contributor and UI documentation that still described the retired Python GUI graph or artwork as living beside UI modules. Production application, presentation and privilege policy remain native C/C++; Python is test-driver/fixture tooling only.
- Clarify that the root changelog is retained consolidated history through the entries it actually contains; exact tags/releases and retained per-release notes are authoritative for later published identities instead of implying a gap-free prose ledger.

## Deliberately unchanged

- No filesystem parser, allocation model, placement algorithm, mutation transaction or recovery implementation changed in this pass.
- The native C++ application-service boundary, format-local native engines and filesystem-neutral C safety core remain cohesive and appropriately owned; they were not split merely because some files are large.
- Infiltratr Common remains pinned to the existing exact gitlink and continues to own only generic mechanisms whose contract is strong enough for Defragmenter.
- ZFS/OpenZFS and Linux swap remain analysis-only by design.
