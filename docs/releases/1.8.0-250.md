# Defragmenter 1.8.0-250

Fix native ZFS analysis rejecting an ordinary OpenZFS pool whose MOS metadnode uses six levels. The analyser's artificial five-level ceiling is replaced with OpenZFS `DN_MAX_LEVELS` geometry: 12 levels for the current minimum block and block-pointer shifts. Existing indirect-block-size, overflow, checksum, compression, vdev and allocation bounds remain fail-closed.

The geometry regression now rejects level 13 instead of incorrectly treating level 6 as unsupported. The complete hosted native/filesystem/GUI suite passed on the source fix, and the ASan/UBSan lane passed. Publication still requires the exact 1.8.0-250 head to pass those same mandatory gates.

This release changes only ZFS analysis geometry and its regression boundary plus release metadata. No writer, UI, Common pin or Test Media formatter/populator behaviour is changed.
