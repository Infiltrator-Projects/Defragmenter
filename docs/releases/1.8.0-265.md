# Defragmenter 1.8.0-265

## Forensic result

This release follows another complete repository-wide forensic review against `PHILOSOPHY.md`, the canonical Infiltrator Engineering Philosophy and the maintained architecture, design, decision, validation, safety, quality and release contracts.

## Significant finding and fix

The review found one genuine release-recovery defect. The quality workflow used `cancel-in-progress: true` for `main`. Because a VERSION change is the release decision, a later ordinary push could cancel the only qualification run carrying that decision; the later run would correctly see no VERSION change and therefore would not publish. The qualified release artefact was also retained for only one day, leaving too small a recovery window for the project's rule that publication must resume the exact already-qualified files rather than rebuild them.

Qualification now serializes `main` candidates instead of cancelling them, and exact SHA-bound release artefacts are retained for seven days. `test_release_gate.py` now treats both properties as release invariants. This removes hidden timing dependence without adding a branch, PR, compatibility path, duplicated builder or second publication authority.

## Broad second-pass result

The filesystem engines, native target-safety core, C++ application services, GTK boundary, privilege/session lifetime rules, registry, Common ownership, build graph, test architecture, Debian packaging, local source installer, release publisher and repository structure were rechecked after the change. No new product-runtime defect justified altering filesystem parsers, planners, writers or recovery state machines.

Large cohesive filesystem implementations were deliberately not split merely for size. The existing filesystem-specific journal schemas were not collapsed into a generic policy layer: Common already owns generic durable-file mechanics, while format-specific transaction phases and recovery identity correctly remain with each engine. The small `install.sh` compatibility entry point remains because it delegates only to the canonical CMake install manifest and does not duplicate installation policy.

Some older exFAT/NTFS implementation files remain unusually compressed stylistically. That is a readability debt, but a repository-wide cosmetic rewrite of qualified destructive code would create a large review surface without strengthening a runtime contract. It is deliberately left for small, subsystem-local readability passes accompanied by the relevant engine qualification rather than mixed into this release-control correction.
